Core formulas and definitions
=============================

Filtered nearest neighbor target:
Given base vectors x_i, labels a_i, query q, and filter range r = [lo, hi], return:

    top-k among { i | lo <= a_i <= hi } sorted by ||q - x_i||_2^2

Recall@K:
For approximate result R_q and exact ground truth G_q:

    Recall@K(q) = |R_q ∩ G_q| / |G_q|

Mean recall:

    R = mean_q Recall@K(q)

Final score:

    S = (QPS / 100) * R^2

E2LSH hash function:
For vector v:

    h_{a,b}(v) = floor((a · v + b) / w)

where:
- a ~ N(0, I)
- b ~ Uniform(0, w)
- w is bin width

Compound key with K hash functions per table:

    H_t(v) = (h_{t,1}(v), ..., h_{t,K}(v))

Multiple L tables reduce miss probability:

    P(miss) = (1 - p(d)^K)^L

where p(d) is the single-function collision probability for distance d.

Filter-augmented vector idea:
For base vector x_i and label a_i:

    z_i = [sqrt(alpha) * x_i ; sqrt(1 - alpha) * normalize(a_i)]

For query q and range [lo, hi], use midpoint m = (lo + hi) / 2:

    z_q = [sqrt(alpha) * q ; sqrt(1 - alpha) * normalize(m)]

Possible label normalization:

    normalize(a_i) = a_i / n_labels

If label is broadcast to d_label dimensions:

    label_vec_i = repeat(a_i / n_labels, d_label)

Then:

    z_i = concat(sqrt(alpha) * x_i,
                 sqrt(1 - alpha) * label_vec_i)

Important: alpha must be tuned. Large alpha behaves like normal vector LSH. Small alpha overemphasizes labels and may hurt vector recall.

Direction 2: Adaptive strategy by filter selectivity
----------------------------------------------------
The filter width varies a lot. A single method may not be optimal for all queries.

Define selectivity:

    sel = (hi - lo + 1) / n_labels

Implement a hybrid search policy:

    if sel <= tau_small:
        use small-range method
    elif sel <= tau_medium:
        use filter-augmented LSH
    else:
        use normal LSH or post-filtering

Candidate methods:
A. Small selectivity:
   - Use exact pre-filter scan if the filtered set is small enough.
   - Since labels are uniform, expected filtered size is approximately:

        |S_f| ≈ N * sel

   - Exact scan cost is O(|S_f| * D).
   - This may be faster than LSH when sel is very small.

B. Medium selectivity:
   - Use filter-augmented LSH.
   - This should reduce wasted candidates while keeping recall.

C. Large selectivity:
   - Use ordinary vector LSH or weakly filter-augmented LSH.
   - Since most candidates pass the filter, pure vector similarity may work better.

Sweep thresholds:
- tau_small: [0.005, 0.01, 0.02, 0.03, 0.05]
- tau_medium: [0.05, 0.10, 0.15, 0.20, 0.30]

    valid_ids = concat(label_to_ids[lo], ..., label_to_ids[hi])

Then exact rerank only those ids.

This improves the small-range exact branch by avoiding boolean mask scans over all N labels.

- Store start/end offsets for each label.
- For a range [lo, hi], use offsets to slice ids efficiently.

Direction 4: Multi-probe LSH around nearby buckets
--------------------------------------------------
Current LSH probes only the exact bucket for each table. To improve recall, also probe nearby bucket keys.

For E2LSH slab vector s = floor((Aq + b) / w), nearby buckets are:

    s + delta

where delta has small values such as:
- one-dimensional +/-1 perturbations
- top few projection dimensions closest to bucket boundary
- limited Hamming radius over slab coordinates

Simpler version:
For each table and each query, generate neighboring keys by changing one of the K slab components by ±1:

    neighbors = {s}
    for j in 1..K:
        neighbors.add(s with s_j + 1)
        neighbors.add(s with s_j - 1)

Then lookup all generated keys.

Expected effect:
- Recall increases.
- Candidate count increases.
- QPS decreases.
